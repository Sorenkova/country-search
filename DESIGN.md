# DESIGN.md

## 1. Как работает отмена запросов

Используется `AbortController`, а не флаг.

- В `src/core/searchController.ts` метод `input()` вызывает `cancelCurrentRequest()` при **каждом** изменении поля, а не только когда сработал debounce. Поэтому устаревший запрос отменяется сразу, как только пользователь нажал следующую клавишу.
- Каждый запуск поиска (`run()`) создаёт новый `AbortController` и передаёт его `signal` в `searchCountries`.
- В `src/core/searchCountries.ts` этот сигнал склеивается с `AbortSignal.timeout(8000)` через `AbortSignal.any([...])`. Результат передаётся в `fetch`.
- Если сработала отмена, `fetch` отклоняется с `AbortError`. Если истёк таймаут, с `TimeoutError`. Различает их `classifyError` (`src/core/classifyError.ts`): `AbortError` молча игнорируется, `TimeoutError` и `HttpError` показываются как ошибка.

**Почему не флаг (`let latest = 0`, `if (id !== latest) return`).**

1. Флаг не отменяет запрос. Браузер скачает ответ, потратит трафик и соединение. `AbortController` обрывает сам запрос: во вкладке Network он помечен как `canceled`.
2. Флаг нужно проверять вручную после каждого `await`. Стоит забыть одну проверку: старый ответ сразу перезапишет новый. С `AbortController` такой проверки нет вообще: отменённый запрос просто не доходит до обработки результата.
3. Сигнал прокидывается в `fetch` как стандартный механизм и композируется с таймаутом (`AbortSignal.any`). Флаг так не может.

## 2. Debounce и его задержка

`debounce(fn, delay)` в `src/core/debounce.ts` написан вручную. Это замыкание с `clearTimeout` / `setTimeout`: каждый новый вызов сбрасывает предыдущий таймер, функция выполняется только после паузы в `delay` мс.

Задержка **300 мс** (`DEBOUNCE_MS` в `src/core/searchController.ts`):

- Средний набор текста даёт примерно 200–300 мс между символами. Пауза 300 мс значит, что человек действительно остановился, а не просто печатает.
- Без debounce каждая клавиша уходит запросом: лишняя нагрузка на API, риск ответа 429 и мигание индикатора загрузки.
- Если поставить больше (600–1000 мс), интерфейс будет казаться подвисшим после ввода.

Таймаут запроса 8000 мс (`REQUEST_TIMEOUT_MS` в `src/core/searchCountries.ts`): достаточно для медленной сети.

Oтдельно: debounce откладывает только **отправку**. Отмена старого запроса от него не зависит (см. раздел 1).

## 3. Сложность `mapCountryResponse`

Пусть B, L, C: число границ, языков и валют одной страны, N: число стран в ответе.

- Одна страна: **O(B + L + C)**. Остальные поля копируются за O(1), массивы границ, языков и валют проходятся по одному разу (`[...borders]`, `.map`).
- Весь ответ (`searchCountries` делает `data.map`): **O(N · (B + L + C))**.
- Память: тоже O(N · (B + L + C)), потому что массивы копируются, и результат не зависит от исходного объекта.
- `debounce`: O(1) на вызов.

## 5. Кэш и дедупликация запросов

Реализованы в `src/core/cachedSearch.ts` (`createCachedSearch`), подключены в `src/main.ts`.

- Ключ кэша: `query.trim().toLowerCase()`, поэтому `Spain` и `spain` это один запрос.
- Кэш это `Map` на 50 записей (`MAX_CACHE_ENTRIES`). При переполнении удаляется самая старая запись, потому что `Map` хранит порядок вставки.
- Дедупликация: второй вызов с тем же ключом, пока первый запрос в полёте, получает тот же промис из `inFlight`, и в сеть второй запрос не уходит.
- У общего запроса свой `AbortController` и счётчик подписчиков. Каждый вызывающий получает собственный промис (`followUntilAborted`), который отклоняется только его `signal.reason`. Отмена одного вызывающего не рушит промис остальных. Сетевой запрос обрывается, когда ушёл последний подписчик.
- Не кэшируются ошибки и отменённые запросы. Пустой результат (404) кэшируется, чтобы «ничего не найдено» не спрашивать повторно.
- Сложность: поиск в кэше и присоединение к запросу в полёте O(1) в среднем, вытеснение O(1). Выдача копирует массив, это O(N), чтобы вызывающий не мог испортить кэш. Память O(K · N), где K ≤ 50.

## 6. История поиска

Реализована в `src/core/searchHistory.ts` (`createSearchHistory`).

- Хранилище передаётся снаружи (`StorageLike`): в ядре нет `window` и `localStorage`, а `src/main.ts` подставляет `window.localStorage` (или заглушку, если доступа нет).
- Хранятся 5 последних уникальных запросов (без учёта регистра), новые сверху. Запрос сохраняется после успешного поиска.
- Повреждённый JSON и ошибки хранилища игнорируются: история удобство, а не обязательная часть.
- Сложность `add`: O(H), где H ≤ 5, то есть фактически O(1).
- Клик по записи (`pickFromHistory` в `src/main.ts`) повторяет запрос. Результат берётся из кэша без обращения к сети.
